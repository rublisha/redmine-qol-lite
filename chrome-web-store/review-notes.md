# Test instructions / комментарий модератору

## Доступ

Расширение работает только с Redmine, где включён REST API, и требует HTTPS URL и персональный API key.

Для полноценной проверки предоставьте модератору отдельный тестовый Redmine и тестовый аккаунт с минимальными правами. Не передавайте рабочий API key или доступ к внутренним данным.

Перед отправкой замените плейсхолдеры:

- Test Redmine URL: `[HTTPS URL]`
- Test username: `[USERNAME]`
- Test password: `[PASSWORD]`
- Test API key: `[API KEY]`

Если Dashboard позволяет хранить credentials отдельно от инструкций, размещайте секреты только в предназначенных для этого полях.

## Шаги проверки

1. Установить расширение и открыть popup.
2. Ввести тестовый HTTPS URL Redmine и API key, нажать «Сохранить и проверить» и подтвердить доступ к этому сайту.
3. Открыть список задач: возле задач появляются звёздочки; наведением на ссылку открывается превью.
4. Открыть задачу: доступны избранное, фильтр истории и сохранённые группы наблюдателей (после создания группы).
5. Открыть диалог добавления наблюдателей, выбрать пользователей и сохранить тестовую группу.
6. Открыть «События» и вручную обновить ленту. При первой проверке старые события намеренно не импортируются.

## Архитектура и данные

- Manifest V3, без удалённого кода, зависимостей и сборочного runtime.
- Все запросы идут напрямую к тестовому Redmine REST API.
- Адрес, API key, настройки и кеши хранятся локально в профиле Chrome.
- Серверов разработчика, аналитики, телеметрии и рекламы нет.
- Optional host permission объявлен широко из-за неизвестного заранее адреса, но запрашивается только конкретный HTTPS-origin, введённый пользователем.
