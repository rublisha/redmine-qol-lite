# Chrome Web Store submission kit

Эта папка содержит материалы для первой публикации Redmine QOL Lite в Chrome Web Store.

## Рекомендуемый режим публикации

Для передачи ссылки друзьям выберите **Unlisted**: карточка не появляется в поиске, но любой человек со ссылкой может установить расширение. Режим **Private** разрешает установку только заранее указанным trusted testers или участникам добавленных Google Groups.

Все режимы видимости проходят одинаковую модерацию и подчиняются одинаковым правилам.

## Содержимое

- `listing-ru.md` — готовые тексты вкладки Store listing.
- `privacy-practices.md` — ответы для вкладки Privacy practices и обоснование разрешений.
- `privacy-policy.md` — политика конфиденциальности; её необходимо разместить по публичному HTTPS-адресу.
- `review-notes.md` — инструкции для модератора.
- `submission-checklist.md` — пошаговая публикация и список ручных действий.
- `screenshot-mode.js` и `screenshot-mode.md` — локальное обезличивание открытой страницы перед снимком.
- `assets/` — иконка, промо-плитка и требования к скриншотам.
- `generate-assets.ps1` — воспроизводимая генерация иконок и промо-плитки.
- `build.ps1` — проверка и сборка ZIP с `manifest.json` в корне архива.

## Сборка

Перед сборкой поднимите patch-версию в `manifest.json`: Chrome Web Store не принимает повторную загрузку с уже опубликованной версией, а имя архива берётся из манифеста.

Из PowerShell в корне репозитория:

```powershell
.\chrome-web-store\build.ps1
```

Готовый архив появится в `chrome-web-store/package/redmine-qol-lite-<версия>.zip`. ZIP и распакованные папки исключены из Git: архив всегда воспроизводится из исходников.

`generate-assets.ps1` запускайте **только если менялась графика** — он перерисовывает `icons/` и `assets/` с нуля. Если иконки не трогали, лишний прогон просто даёт диф в трекаемых PNG.

### Что делает `build.ps1`

1. Читает версию из `manifest.json`.
2. Проверяет, что все runtime-файлы из списка `$runtimeFiles` на месте, и прогоняет `node --check` по каждому `*.js`.
3. Проверяет, что все иконки, указанные в `manifest.json`, существуют.
4. Собирает ZIP: файлы расширения в корне архива, иконки — в `icons/`.
5. Перечитывает готовый архив и падает, если `manifest.json` не в корне, если имя записи содержит `\`, если внутрь попали `.git`, `chrome-web-store` или `AGENTS.md`, либо если не хватает иконки из манифеста.

Список `$runtimeFiles` в скрипте задан явно. **Новый content script нужно добавить в три места**: `SCRIPT_FILES` в `background.js`, `$runtimeFiles` в `build.ps1` и в раскладку репозитория в `AGENTS.md`. Иконки скрипт забирает из папки `icons/` целиком, их перечислять не нужно.

### Почему архив собирается вручную, а не через `Compress-Archive`

`Compress-Archive` в Windows PowerShell 5.1 пишет внутрь архива пути с разделителем `\` (`icons\icon-128.png`), хотя спецификация ZIP требует `/`. Chrome разворачивает такую запись как файл с обратным слэшем в имени, а не как папку, и иконки из манифеста перестают находиться. Поэтому скрипт создаёт записи сам через `ZipFileExtensions::CreateEntryFromFile` с явными именами и отдельно проверяет отсутствие `\` в готовом архиве.

### Проверка архива перед загрузкой

Скрипт проверяет только структуру. Распакуйте готовый ZIP во временную папку и загрузите **именно её** как unpacked extension — так проверяется ровно то, что уедет в стор, а не рабочее дерево. Дальше пройдитесь по popup, списку задач, странице задачи, превью, событиям, избранному, истории и группам наблюдателей.

## Что нельзя класть в материалы

Не используйте реальные API key, внутренние URL, имена сотрудников, номера и содержимое закрытых задач. Скриншоты делайте на тестовом Redmine с вымышленными данными.
